## 1. 快速开始

### 1.1 构建

```bash
# Windows（MinGW + MS-MPI + OpenMP）
cmake -S . -B build -G "MinGW Makefiles" -DPSO_ENABLE_MPI=ON -DPSO_ENABLE_OPENMP=ON
cmake --build build --parallel

# Linux（不需要 -G 一行）
cmake -S . -B build -DPSO_ENABLE_MPI=ON -DPSO_ENABLE_OPENMP=ON && cmake --build build --parallel
```

构建完成后得到三个可执行文件（Windows 带 `.exe`）：

| 可执行文件 | 入口 | 一句话 |
|---|---|---|
| `pso_serial` | 串行 | 单进程基线；编译启用 OpenMP 后可用线程 |
| `pso_mpi_ms` | MPI 数据并行 | 同一群粒子分块更新，结果与串行逐位一致 |
| `pso_mpi_island` | MPI 环形岛模型 | 多个岛独立演化、周期交换移民（本项目主推方案） |

### 1.2 第一个优化

```bash
./build/pso_serial --function sphere --particles 16 --dim 2 --max-evals 6400 --seed 20240229
```

真实输出（一整行，此处为阅读折行）：

```text
record=result schema=pso_v1 implementation=serial function=sphere particles=16 dim=2
max_evals=6400 max_iters=1000 seed=20240229 boundary=reflect dynamics=constriction
target=1e-08 lower=-100 upper=100 chi=0.72984 c1=1.49618 c2=1.49618 vmax_ratio=0.2
inertia_start=0.9 inertia_end=0.4 ranks=1 threads=20 migration_interval=0
iterations=82 evals=1328 best=1.8032187541123875e-09 success=1 fes_to_target=1328
stop_reason=target stop_on_target=1 timing_scope=solver elapsed_max_s=0.006166400
```

这一行分两部分：

**回显你的配置**（输入参数的确认）：`implementation`、`function`、`particles`、
`dim`、`max_evals`、`max_iters`、`seed`、`boundary`、`dynamics`、`target`、
`lower`、`upper`、`chi`、`c1`、`c2`、`vmax_ratio`、`inertia_start`、
`inertia_end`、`ranks`、`threads`、`migration_interval`。含义见第 4 节，
完整定义见 docs/06。

**本次运行的结果**（学习者最该先看的六个字段）：

| 字段 | 本例值 | 含义 |
|---|---|---|
| `best` | 1.803e-09 | 找到的最优（最小）函数值 |
| `success` | 1 | 是否达到 `target`（1=达到，0=未达到） |
| `evals` | 1328 | 实际消耗的函数评估次数（16 粒子 × 83 代） |
| `iterations` | 82 | 实际演化的代数 |
| `fes_to_target` | 1328 | 首次达到 target 时的评估次数 |
| `stop_reason` | target | 停止原因：`target`（达标早停）或 `evals`（预算耗尽） |
| `elapsed_max_s` | 0.0062 | 墙钟时间（秒）；不含种群初始化；MPI 下取各 rank 最大值 |

注意 `evals=1328 < max_evals=6400`：达到 target 后提前停止，预算没有用完。
想跑满预算做公平比较，加 `--no-early-stop`。

### 1.3 看看收敛过程

```bash
./build/pso_serial --function sphere --particles 16 --dim 2 --max-evals 6400 \
  --seed 20240229 --history /tmp/demo.history
cat /tmp/demo.history
```

轨迹文件（sidecar）每代一行，记录截止到该代的全局最好值：

```text
iteration=0 evals=16 best=1071.800469473302
iteration=1 evals=32 best=192.81427435778758
iteration=2 evals=48 best=2.5286737577767631
```

`iteration=0` 是初始种群。用 `scripts/analyze_convergence.py` 或
`scripts/plot_results.py --plot` 可以汇总与画图（见 6.3）。

### 1.4 用 MPI 跑

数据并行入口（2 个 rank）：

```bash
"/c/Program Files/Microsoft MPI/Bin/mpiexec.exe" -n 2 ./build/pso_mpi_ms \
  --function sphere --particles 16 --dim 2 --max-evals 6400 --seed 20240229
```

```text
record=result schema=pso_v1 implementation=mpi-data-parallel function=sphere ... ranks=2 ...
iterations=82 evals=1328 best=1.8032187541123875e-09 success=1 fes_to_target=1328 ...
elapsed_max_s=0.010140500
```

**关键观察**：`best`、`evals`、`iterations` 与 1.2 的串行运行**逐位相同**。
这是架构不变量 1——固定 `(函数, 维度, 粒子数, 预算, seed)` 时，数据并行只改变
速度，不改变计算结果，且与 rank 数无关。自己换 `-n 4` 再跑一次验证。

环形岛模型入口（4 个岛，每岛 8 粒子，每 5 代迁移一次）：

```bash
"/c/Program Files/Microsoft MPI/Bin/mpiexec.exe" -n 4 ./build/pso_mpi_island \
  --function sphere --particles 32 --dim 2 --max-evals 12800 \
  --seed 20240229 --migration-interval 5
```

```text
record=result schema=pso_v1 implementation=mpi-island function=sphere ... ranks=4 ...
iterations=46 evals=1504 best=1.0515495621938213e-10 success=1 ...
elapsed_max_s=0.007708100
```

**关键观察**：岛模型的结果与串行**不同**（best=1.05e-10 vs 1.80e-09）。这不是
bug，是设计豁免（docs/02 §3.3）：每个岛按 `0x100000000 + rank` 派生随机流命名
空间，因此岛模型结果**故意**随 rank 数变化。比较岛模型时必须固定 rank 数。

另外注意本例 MPI（0.0077–0.0101 秒）比串行（0.0062 秒）**慢**：进程启动开销
在毫秒级任务里占主导。并行加速在大规模预算下才显现，可引用的数字见 docs/03。

### 1.5 本次运行验证的关键性质

1. **可复现**：同一条命令重跑，结果行逐位相同（随机流由 seed 确定性派生）。
2. **rank 不变性**：serial 与 mpi-ms 任意 rank 数结果相同；island 按设计豁免。
3. **早停与预算**：`success=1`、`stop_reason=target`、`evals < max_evals`。

## 2. PSO 基本概念与术语

粒子群优化（Particle Swarm Optimization）模拟一群鸟觅食：每只鸟（粒子）在
搜索空间里有一个位置和一个速度；每只记住自己飞过的最好位置（pbest），群体
共享当前最好位置（social best）；下一步速度由三部分合成——惯性（保持原方向）、
认知（飞向自己的 pbest）、社会（飞向群体的 social best。

本项目需要知道的术语：

| 术语 | 含义 |
|---|---|
| 粒子 / 位置 / 速度 | 搜索空间中的一个候选解 / 其坐标 / 每维一个分量 |
| pbest | 单个粒子的历史最好位置及适应度 |
| social best | 当前代用于社会项的位置（串行与数据并行为全局；岛模型为本岛） |
| 代（iteration） | 所有粒子各更新一次并各评估一次 |
| 评估（evaluation） | 对单个位置求值一次；一代 = particles 次评估 |
| 预算（max-evals） | 统一的评估次数上限；不同 particles 配置之间用它比较才公平 |
| 收缩因子（χ） | 默认动力学；`chi=0.72984`、`c1=c2=1.49618`（Clerc-Kennedy） |
| 线性惯性（w） | 对照动力学；`--linear-inertia`，w 从 0.9 递减到 0.4 |
| 边界处理 | 粒子越界后的处置：`reflect`（反弹）/ `clamp`（截断）/ `reinit`（重采样） |
| 早停 | 达到 `target` 即停（`--no-early-stop` 关闭） |
| 迁移 | 岛模型每 `--migration-interval` 代沿环交换最优/最差粒子 |

**为什么用评估次数而不是迭代数做预算**：`particles=16` 跑 82 代与
`particles=20000` 跑 1 代都消耗 1328 次评估，但前者搜索得更充分。统一按评估
次数度量，配置之间才可比。

## 3. 入口选型

| 你想… | 用 | 注意 |
|---|---|---|
| 建立基线、调试、单机求解 | `pso_serial` | 结果作为其他入口的正确性参照 |
| 同一群粒子分给多进程，要求结果与串行一致 | `pso_mpi_ms` | 保留作对照方案；加速来自评估分摊 |
| 多岛独立演化 + 周期迁移，追求可扩展的质量/加速 | `pso_mpi_island` | 本项目主推方案；结果随 rank 数变化（设计使然） |

深入原因见 [02-优化设计方案.md](02-优化设计方案.md)（维护者向）。

## 4. 常用参数与选择建议

最常用选项（完整定义、取值范围与全部选项见 docs/06）：

| 选项 | 默认值 | 什么时候动它 |
|---|---|---|
| `--function NAME` | `rastrigin` | 换测试问题（见第 5 节） |
| `--particles N` | 20000 | 群体大小；越大越稳、每代越贵 |
| `--dim N` | 50 | 问题维度 |
| `--max-evals N` | 1000000 | 统一预算；做比较时固定它 |
| `--max-iters N` | 1000 | 仅 `--max-evals 0` 时生效 |
| `--seed N` | 20240229 | 复现；多次运行取统计时逐个换 |
| `--target X` | 1e-8 | 成功阈值；达到即早停 |
| `--boundary MODE` | `reflect` | 越界策略实验（clamp/reinit） |
| `--linear-inertia` | 关 | 切换到 w=0.9→0.4 对照动力学 |
| `--no-early-stop` | 关 | 固定预算比较时打开 |
| `--pin-cpus` | 关 | 计时实验绑核（协议见 docs/03） |
| `--history PATH` | 无 | 保存逐代收敛轨迹 |
| `--migration-interval N` | 10 | 岛模型迁移周期 |
| `--verbose` / `--quiet` | quiet | 打印/关闭进度行 |

参数选择三原则：

1. **固定预算比结果**：比较不同配置时固定 `--max-evals`，别比迭代数。
2. **多次运行才下统计结论**：单次运行只说明格式；≥30 个 seed 的统计协议见
   docs/03（配对 Wilcoxon + bootstrap）。
3. **先别动 χ/c1/c2/vmax_ratio**：默认值是标准收缩因子设定；想改先读
   [05-PSO算法与优化理论.md](05-PSO算法与优化理论.md) 的稳定性依据。

## 5. 基准函数

| 名称 | 搜索范围 | 最优值 | 特点 |
|---|---|---|---|
| `sphere` | [-100, 100] | 0（原点） | 单峰，最简单，适合 first test |
| `rosenbrock` | [-100, 100] | 0（全 1） | 狭长山谷，考验沿谷前进 |
| `rastrigin` | [-5.12, 5.12] | 0 | 大量局部极小，考验全局搜索 |
| `griewank` | [-600, 600] | 0 | 多峰 + 乘积项，大范围 |
| `ackley` | [-32.768, 32.768] | 0 | 多峰 + 指数外框 |

默认函数为 `rastrigin`。五个函数都是轴对齐、未平移的经典函数，适合学习与
回归测试；性能结论的可推广性以 docs/03 的限定表述为准（社区基准套件如
CEC-2013 的出处见 docs/07 [R13]）。

## 6. 常见任务

### 6.1 复现一次运行

同一条命令即可，结果行逐位一致。记录命令与输出行就是完整的复现信息
（配置全部回显在结果行里）。

### 6.2 多次运行与统计分析

换 `--seed` 逐个跑，用 `scripts/analyze_stats.py` 做配对比较：

```bash
python scripts/analyze_stats.py --help
```

### 6.3 画收敛曲线

跑一次带 `--history` 的运行，然后：

```bash
python scripts/analyze_convergence.py --help
# 或生成汇总表与图（需要 matplotlib，缺失时自动跳过绘图）
python scripts/plot_results.py --manifest-root <目录> --output /tmp/summary.csv --plot /tmp/curve.png
```

### 6.4 固定预算比较两种动力学

```bash
./build/pso_serial --max-evals 100000 --seed 20240229 --no-early-stop
./build/pso_serial --max-evals 100000 --seed 20240229 --no-early-stop --linear-inertia
```

两次的 `--max-evals` 相同，比较 `best` 即公平。

### 6.5 跑岛模型实验

```bash
"/c/Program Files/Microsoft MPI/Bin/mpiexec.exe" -n 4 ./build/pso_mpi_island \
  --function rastrigin --particles 2000 --dim 20 --max-evals 200000 \
  --seed 20240229 --migration-interval 10
```

岛模型结果随 rank 数变化（设计使然），实验必须固定 rank 数；加速比要按
docs/03 协议采集（`--pin-cpus`、≥30 seed）。

### 6.6 生成正式实验计划

`scripts/run_experiments.py` 默认 dry-run（只写计划不执行）：

```bash
python scripts/run_experiments.py --help
```

正式采集协议、环境要求与已冻结的结果数字见 docs/03；本文不重复性能结论。

## 7. 故障诊断

| 症状 | 原因 | 处理 |
|---|---|---|
| 构建日志说 MPI 关闭 | 未找到 MS-MPI/OpenMPI | 安装后重新 configure；无 MPI 时只能构建 serial |
| `There are not enough slots` | OpenMPI 槽位不足 | 命令前加 `--oversubscribe`（本仓库 CTest 已自动带） |
| `unknown option: --xxx` | 选项不存在或拼错 | `--help` 查看合法选项；注意没有 `--ranks`（rank 数由 `mpiexec -n` 给） |
| `invalid option value` | 值域校验失败 | 检查 `particles>0`、`dim>0`、`lower<upper`、`max-evals>=particles` |
| 结果行后没有进度输出 | 默认安静 | 加 `--verbose` |
| mpi-ms 结果与 serial 不同 | 不该发生 | 这是缺陷，请带命令与两行输出报告 |
| mpi-island 结果与 serial 不同 | 设计豁免（docs/02 §3.3） | 预期行为；比较时固定 rank 数 |
| 计时数字波动大 | 单次运行受调度影响 | 用 `--pin-cpus` 并遵循 docs/03 协议；单次运行不可引用 |
| 写 history 失败（退出码非零） | 路径不可写/磁盘满 | 换可写路径；求解器对写失败硬失败而非静默丢弃 |
