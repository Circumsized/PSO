## 当前可复现实测

本报告保留历史采集的性能与质量数字。当前验证环境是 Windows 11、GCC 16.2.0（WinLibs UCRT POSIX）、Microsoft MPI 10.1。历史 Windows 正式采集的原报告记录为 GCC 16.1.0；manifest 未记录求解器编译器版本，不能用当前版本替代该历史记录。

历史主机为 i7-12700H（6 性能核×2 线程 + 8 能效核 = 20 逻辑核）。主计时数据位于 `formal-20260912-v5-pinned`，未绑核对照位于 `formal-20260912-v4`，第二环境子集位于 `formal-20260912-linux`。历史比较记录为 v4/v5 的 best 相同；Linux 的 25/1260 条差异不超过 5.7e-14。具体范围见各节。

数值异常处理、统计校验与分位数实现的修复不等于重新采集性能数据。下方计时表描述历史二进制；不能用本轮功能回归推导新的速度比。

## 正式实验协议与命令

正式矩阵先 dry-run 并审阅 manifest：

```bash
python scripts/run_experiments.py --mode all --functions sphere,rastrigin \
  --particles 2000 --particles-per-rank 2000 --dim 50 --max-evals 100000 \
  --ranks 1,2,4,8 --threads 1,2 --runs 30 --output-dir results/formal-plan
# 审核 manifest.json 后才增加 --execute；默认拒绝向非空日志追加。
```

完整消融矩阵（boundary × dynamics）需显式展开选项：

```bash
python scripts/run_experiments.py --mode ablation --functions rastrigin \
  --particles 2000 --dim 50 --max-evals 100000 --ranks 1,4 --threads 1 \
  --boundaries reflect,clamp,reinit --dynamics constriction,linear-inertia \
  --runs 30 --output-dir <dir>/07-ablation-full --execute
```

`results/formal-plan-20260911-v2/` 是仅计划的 manifest（未执行）；`results/formal-20260911/` 是一次被宿主中止的部分运行，已用 `INVALID_PARTIAL_RUN.txt` 标记并排除。

快速三实现链路可用 `PYTHON=python ./scripts/run_benchmark.sh 30 2000 50 100000`；该链路已统一为 `--no-early-stop --pin-cpus`，但仍是单次采集、无 manifest、无法保证采集期机器空闲，**其 `elapsed` 列与 `smoke_summary.csv` 不构成任何可引用的计时结论**。Windows 使用 Git Bash/MSYS 时，脚本会把可执行路径转换为 Windows 格式；可用 `MPIEXEC` 指向 MS-MPI。注意该脚本每次运行会覆盖 `results/raw_*.log` 快照；正式数据一律走 `run_experiments.py` 的独立目录。

每个配置使用 30 个 seed，固定函数评估预算；套件定义：

| 组别 | 函数 | 维度 | 粒子数 | 进程数 | 目的 |
|---|---|---:|---:|---:|---|
| baseline | sphere/rastrigin | 50 | 2000 | 1 | 串行参考 |
| strong（data-parallel/island） | sphere/rastrigin | 50 | 2000 | 1/2/4/8 × 线程1/2 | 固定总负载强扩展 |

## 正式实验结果（2026-09-11 本机采集）

### 采集条件与数据溯源

平台：i7-12700H（6P×2 线程 + 8E = 20 逻辑核）、GCC 16.1.0（WinLibs UCRT）、Microsoft MPI 10.1、OpenMP 5.2。所有运行 `--no-early-stop`、`OMP_DYNAMIC=FALSE`、`OMP_NUM_THREADS=<配置线程数>`；v5 另加 `--pin-cpus`（拓扑感知绑核，OpenMP 线程在其进程掩码内调度）。计时 `timing_scope=solver`：**从初始 swarm 生成之后起表**（串行 `pso_swarm_init_range` → `pso_wall_time`，MPI 侧 `MPI_Barrier` → `MPI_Wtime`），故含全部迭代的评估与集合通信，不含进程启动、粒子初始化（初始 `particles` 次评估在表外）与最终归约。三种实现的起表点一致，跨实现的速度比仍公平。每配置 30 个连续 seed（20240229 起），所有 run 均未命中 1e-8 target，成功率 0%，`fes_to_target` 恒为预算上限。manifest 未记录 CPU 型号、编译器与 OpenMP 版本（`host` 只记录平台与 Python 版本）；且 MS-MPI 的 `mpiexec` 不支持 `--version`，版本探测失败，manifest 记录 `version=null`、`version_returncode=4294967295`——上述平台信息来自本报告的文字记录，不能用当前工具链版本替代该历史记录。

数据目录 `results/formal-20260911-v3/`（2460 run 主矩阵 + 360 run 消融，manifest 全部 completed、returncode 0）。溯源：主矩阵第一轮执行到第 1870 条时 manifest 原子替换被 Windows 文件锁（WinError 5）中断；`write_manifest_atomic` 增加 PermissionError 退避重试（含单测），随后以 `--append` 重跑完整矩阵。`--append` 不做任何去重：它只豁免“日志非空即拒绝”与 manifest 覆盖守卫，在旧日志行之后继续记录，重复 seed 会被 `plot_results.py` 等解析工具硬失败——**所有统计仅来自第二轮完整采集**，第一轮残样未进入统计。汇总：`summary.csv`（按配置分组，相同配置跨套件合并，如 island r1/t1 的 strong+weak+ablation 样本合并为 90–120 run 组）。

mpiexec 绑核对册口径：采集工具此前只对 MS-MPI 设 `MPIEXEC_AFFINITY=0` 关闭 mpiexec 绑核，OpenMPI 不认该变量、自 1.8 起默认即绑核（np≤2 绑 core、np>2 绑 socket），故 Linux 上 pin=false 的「未绑核对照」实为默认绑核、与 Windows MS-MPI 的不绑核对照不同构。今后 `run_experiments.py` 探测到 OpenMPI 时：所有 run 追加 `--oversubscribe`（槽位不足的 runner 上 OpenMPI 会拒绝 `-n N`，与 CMakeLists 的版本串判别一致），pin=false 另加 `--bind-to none`，恢复与 MS-MPI 的同构「不绑核」语义；这是采集口径的完善，不改动已冻结的计时数字。历史 Linux 批次 `results/formal-20260912-linux/` 确系在 OpenMPI 默认绑核下采集，该事实保留不改写；该批次仅用于算法层逐位复现比对，其计时本就不引用。

依据：OpenMPI `mpirun(1)` man page（v4.1，https://www.open-mpi.org/doc/v4.1/man1/mpirun.1.php ）载明「自 v1.8 系列起 mpirun 自动绑核」，无进一步指令时 np≤2 绑 core、np>2 绑 socket、超售时不绑核，`--bind-to none` 为官方定义的关闭途径；MS-MPI 侧 `MPIEXEC_AFFINITY` 取 0 即 "No affinity"（Microsoft Learn HPC Pack 的 mpiexec 环境变量文档；MS-MPI 一方源码 `mp_parse_command_line.cpp` 的 `-help3` 清单同证），且未指定该变量时 MS-MPI mpiexec 默认 spread 绑核——显式置 0 正是覆盖默认行为。两个外部依据及其限制见 [docs/07](07-参考文献与文档写作约定.md) [R9]/[R10]。

### 亲和性绑定与主数据集 v5-pinned（2026-09-12）

`--pin-cpus` 把每个求解进程绑定到拓扑感知的固定逻辑 CPU：枚举物理核（Windows `GetLogicalProcessorInformation` / Linux sysfs `thread_siblings_list`），按每核兄弟线程数降序稳定排序（本机 P 核在前、E 核在后），全局线程索引 `i = rank×threads + k` 轮转分配 `核 = 排序核[i mod 核数]`、槽位 `i div 核数`（不超售时线程各占独立物理核，SMT 兄弟不共享）。失败即整体中止（`MPI_Allreduce` 集体一致），绝不允许某 rank 静默退化为未绑定。

**v5-pinned 主矩阵**（`results/formal-20260912-v5-pinned/`）：同一 2820 run 协议（主 2460 + 消融 360），全程 `--pin-cpus`、机器空闲单轮干净采集（任何后台负载都会污染 per-rank 极小运行时长——本仓库曾据此丢弃过一次受污染采集）。与 v4 未绑核数据逐 seed 逐位一致（2820/2820 对 best 完全相同）：**亲和性只影响调度，不改变计算**。

### 质量结论（固定 100k 评估，best 中位数，30 seeds）

1. **数据并行质量与 rank 数严格无关**：rastrigin 所有 rank 配置 best 中位均为 205.2910，sphere 均为 212.8148——全局粒子流映射使同 seed 问题实例与 rank 划分无关，这是 RNG 修复的直接实证。
2. **岛模型质量随 rank 增加而退化**：sphere 217（r1）→ 240（r2）→ 332（r4）→ 444（r8）；每岛粒子变少削弱全局搜索。岛模型换时间不换质量，大规模使用需配合迁移调参。
3. **当前 Rastrigin 50D 消融中，linear-inertia 的 best 更小**：中位数约 117–128，对照约 191–223。相同岛配置下，两种动力学按 seed 标识配对；历史 Wilcoxon signed-rank 结果为 6 组全部 T=0、每组 30/30 对偏向 linear-inertia、近似 p=1.8e-6。Mann–Whitney U 作为独立样本对照，历史 z 介于 -6.16～-6.63、p 介于 3.3e-11～7.4e-10（最小为 r4/clamp 的 3.338e-11），最弱组 r1/clamp z=-6.1577、p=7.38e-10。两种检验的 p 值不是效应量，不宜按大小判断谁更乐观；结论仅适用于所测函数、维度、预算和配置。
4. **边界策略差异较小**：constriction 下 reinit（191–211）略优于 reflect（203–223）与 clamp（199–217）；linear-inertia 下三者接近。

### 统计方法与可复现性

- 速度比置信区间：配对 bootstrap（同 seed 联合重采样 seed 索引，10,000 次，RNG seed=20240229，确定性），`python scripts/analyze_stats.py <baseline_log> <candidate_log> --metric time`；整表复现 `python scripts/analyze_speedups.py --manifest-root <集合>`。两次采集的逐位比对 / 跨环境复现：`python scripts/compare_best_values.py --a <集合A> --b <集合B> [--tol 0] [--allow-subset]`（v4↔v5 要求 tol=0 逐位一致；跨平台允许 ≤5.7e-14（2 ULP） 的浮点噪声）。
- 质量比较：Wilcoxon signed-rank 使用非零差值的平均秩、并列秩方差校正和连续性校正；Mann–Whitney U 保留作对照。二者都是正态近似，没有小样本精确分支。五个无并列、同号差值的近似 p 约为 0.0591；五个相等同号差值可得到约 0.03689。不能把前者推广为所有小样本的显著性下限。
- 有限性与完整性：统计入口拒绝 NaN/Inf，时间比要求严格正值；未完成数据、种子错配和重复记录不能进入统计。分位数允许单个重采样值，但这种退化区间不表示高精度，正式分析仍使用 10,000 次重采样。参考依据见 [文献与写作约定](07-参考文献与文档写作约定.md)。

### 复采与收敛轨迹（2026-09-12，`results/formal-20260912-v4/`）

同一协议的完整复采：2820 run（主矩阵 2460 + 消融 360）**单轮干净跑完**（重试修复后无中断），并新增每 run 的 best-so-far 轨迹 sidecar（`--history`，共 2820 份，`iteration/evals/best` 三元组、单调不增校验）。复采结论与 v3 一致且 CI 重叠：dp rastrigin r8t1 速度比 x4.11 [4.05, 4.19]（v3: x4.24 [4.08, 4.36]）、island r8t1 x4.21 [4.12, 4.35]、sphere dp r8t1 x3.43 [3.27, 3.62]。

2026-09-12 晚的 v5-pinned 复采（**为绑核重编译的二进制**——新增 `pso_pin.c`/`--pin-cpus`，manifest 记录的 sha256/体积与 v4 不同——锁核、空闲单轮）与 v4 的 2820 对逐 seed best 值**逐位一致**（`compare_best_values.py --tol 0`；跨构建仍逐位相同），收敛中位轨迹表与 ERT 输出与 v4 完全相同——亲和性调度对结果不可见。本节的轨迹与 ERT 数字对两个数据集同时成立。

轨迹层证据比终点值更强：**数据并行在所有 eval 检查点（10k/25k/50k/100k）的 best-so-far 中位逐位相同**（rastrigin 全 rank/线程均为 451.2→404.3→343.9→205.3；sphere 均为 20020→6756→1511→212.8），且线程数不改变任何轨迹——确定性设计的完整实证。岛模型则在每个检查点都劣于串行（sphere r8 在 50k 时已差 68%：2543 vs 1511）。
